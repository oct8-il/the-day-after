Item pass · Acceptance Test Procedure

docs/method/pass-atp.html · v1.1 · 27 Sep 2026 · applies to every published incident's pass (DIA-306 sub-issues) · criteria: docs/method/pass.md v2

1 · Purpose and scope

This procedure decides whether one item's pass is accepted. It applies the same way to every published incident, i01 to i33. It tests the rebuilt record (claims, search log, authored text, photos) against pass.md. It does not test the site's code.

Each run of this procedure on an item produces an Acceptance Test Record (ATR): docs/passes/<id>-atr.html, generated by npm run atp -- <id>. The generator fills in every automatic test and lays out the material for each manual one.

2 · Roles

  • Researcher (Claude): runs the pass, makes the automatic tests pass, generates the ATR, and hands over with the Linear sub-issue set to In Review.
  • Editor (Roy): runs the manual tests on the ATR and gives the verdict.

3 · Entry conditions

  1. The pass is committed on the pass branch, and the incident file carries a pass block.
  2. Photos are in public/photos/, with originals in photographs/.
  3. The ATR has been generated from the committed state and shows no automatic failures. Otherwise the researcher is not done and the item is not handed over.

5 · Acceptance

Accepted when T01–T15 all pass and the editor passes T16–T25. The researcher then moves the item's sub-issue to Done and the pass goes to dev.

Rejected when any test fails. The editor replies with the test IDs and what to change. The researcher fixes, regenerates the ATR, and hands it back. Only the failed tests and anything the fix touched are re-run.

Deadline: an item not accepted by 1 Oct 2026 leaves published.json (DIA-306).

6 · Records

  • One ATR per item: docs/passes/<id>-atr.html, committed with the pass.
  • The verdict and failed test IDs go on the item's Linear sub-issue (DIA-308…336).
  • npm run check:passes lists which items are passed.

Target editor time: about 15 minutes per item, mostly T16, T18 and T25.
