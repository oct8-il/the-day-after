The outward channels

Slide 5's sealed ballot promises that the answer opens later. The pill under it opens the updates sheet, which is the one place the item page asks a reader for anything. This file is how that sheet is switched on: six values, where each comes from, and what happens when one is missing.

1 · What this governs

One screen: the updates sheet behind slide 5's pill עדכנו אותי כשהמענה ייפתח. It holds a mail form, a divider, and two rows — a WhatsApp group and the Instagram account. Nothing else on the site reads these values.

No provider is chosen in the code. What the build knows is that a mail list takes an HTTP POST with an address in it. Which list that is, what it promises and what its privacy line says are DIA-435's, still open. So the endpoint is a whole URL and the field names are values: switching between Buttondown, Kit, Mailchimp or a plain form service is four values and no commit.

Nothing ships dead. A control that cannot do what it says is not drawn. With no endpoint, neither the pill nor the sheet behind it exists and the slide ends at the ballot — which is the shape every deployment has today. With no WhatsApp link, that row is not drawn. Instagram has no dependency.

2 · The six values

All six are read in next.config.mjs and handed to the app as NEXT_PUBLIC_*, the same way the environment and the data pool are. You set the plain name; the prefix is added for you.

namewhat it isdefaultempty means
NEWSLETTER_ACTION The form's action — the whole URL the address is posted to. none No pill and no sheet. The slide ends at the ballot.
NEWSLETTER_EMAIL_FIELD What that endpoint calls the address. email Falls back to email.
NEWSLETTER_PAGE_FIELD Where the page the reader was on goes, with its hash — so a mail sent later can say which failure it is about. none The page is not sent. The sign-up still works.
NEWSLETTER_HIDDEN Whatever else that endpoint needs, as a query string: embed=1, a list id, a bot-trap. Parsed into hidden inputs and not interpreted. none No extra fields are sent.
WHATSAPP_INVITE_URL The group or channel invite link. none The WhatsApp row is not drawn.
INSTAGRAM_URL The account. https://instagram.com/oct8.co.il Falls back to the default.

Every URL among them must be https://. An http value fails the build with the variable's name in the error rather than being silently downgraded — these are the only places the item page sends a reader off-site, and one of them takes an address.

3 · Switching the mail list on

  1. Create the list with whichever provider DIA-435 settles on. The only requirement from this side is that it accepts a plain HTML form POST — no JavaScript SDK and no API key. Every major one does; it is how their "embed" snippet works.
  2. Copy its HTML embed snippet out of the provider's dashboard. You are not going to paste it anywhere — you are going to read four values off it.
  3. Read the four values. From <form action="…"> take NEWSLETTER_ACTION. From the visible e-mail <input> take its name — that is NEWSLETTER_EMAIL_FIELD. Every <input type="hidden"> in the snippet becomes one key=value pair in NEWSLETTER_HIDDEN, joined with &. If the provider supports a custom or metadata field, name it in NEWSLETTER_PAGE_FIELD; if it does not, leave it empty.
  4. Set them on the deployment (§6) and redeploy.
  5. Verify with one real address (§7). This step is not optional — see the warning there.

What the four look like

Illustrations, not instructions: read yours off your own snippet, because these change and the id in each is yours.

providerACTIONEMAIL_FIELDHIDDENPAGE_FIELD
Buttondown https://buttondown.com/api/emails/embed-subscribe/<username> email embed=1 metadata__page
Kit https://app.kit.com/forms/<form-id>/subscriptions email_address — fields[page]
Mailchimp https://<dc>.list-manage.com/subscribe/post EMAIL u=…&id=… a merge field, if you make one
a plain form service https://…/f/<form-id> email — page
Mailchimp's e-mail field is not always EMAIL — some accounts' generated snippets call it MERGE0. This is exactly why the name is a value and not code: read it off your own form.

Worked example

NEWSLETTER_ACTION=https://buttondown.com/api/emails/embed-subscribe/oct8
NEWSLETTER_EMAIL_FIELD=email
NEWSLETTER_PAGE_FIELD=metadata__page
NEWSLETTER_HIDDEN=embed=1

How the send actually works

The form is submitted by the browser into a hidden <iframe> — a real HTML form POST, not a fetch. Three reasons, and they are why the provider must accept a plain form:

  • A static export has no server, so there is no key to keep. The embed endpoints want none.
  • A navigation would throw the reader out of Instagram's in-app browser, which is where most of them will be, and lose the failure they were reading.
  • No CORS negotiation to fail: a form POST is allowed to any origin.

The cost is in §7.

4 · WhatsApp

WHATSAPP_INVITE_URL is the invite link for the silent updates group. The row reads קבוצת עדכונים בוואטסאפ · שקטה. רק אנחנו כותבים, רק כשיש מה. and it is not drawn while the value is empty, which is where DIA-446 stands today.

Before it is set, that issue wants four things decided: the group created with only admins can send on (or a Channel, which is one-way by design and does not show every member's phone number to every other member); a phone number for it that is not a personal one; a rule for rotating the link if it leaks, remembering that on a static site a link change is a deploy; and a privacy line on /about naming WhatsApp as a third party the reader chooses to join.

A WhatsApp group shows every member's phone number to every other member. That is a real disclosure to make on a site about accountability, and it is the argument for a Channel. Decide it on DIA-446, not here.

5 · Instagram

INSTAGRAM_URL defaults to the project's account, so this row ships without configuration. The row reads @oct8.co.il · נפרסם שם כשהמענה ייפתח. — which is a promise, and it belongs to whoever runs the account on the day.

The handle is a latin run inside a Hebrew line, so it is isolated with <bdi> rather than dir="ltr": the second would push it to the wrong end of its own row.

6 · Where to set them

On the deployment

Project settings → Environment Variables. Plain names, no NEXT_PUBLIC_ prefix. Set them for every environment you want the sheet on; a change needs a redeploy, because a static export bakes them into the HTML.

Staging first. Set them on staging, send yourself one real address, and only then put them on prod. Nothing about this can be tested after the fact from the site itself.

Locally

NEWSLETTER_ACTION=https://example.invalid/list \
NEWSLETTER_PAGE_FIELD=page \
NEWSLETTER_HIDDEN=embed=1 \
npm run dev

Any URL will do while you are looking at the screen — the sheet will report a failure when the post does not land, which is the failure state working. Add WHATSAPP_INVITE_URL=https://chat.whatsapp.com/… to see the second row.

In CI

.github/workflows/build.yml sets the endpoint to https://example.invalid/not-a-real-list on the artifact the test jobs are served. That artifact is never deployed. Without it, eleven of the twelve sheet tests would skip themselves — the shape a deployment has today is the one with no pill, and a shape with nothing in it is a shape the tests cannot test. The suite answers every off-site request itself, so nothing leaves the runner whatever the endpoint is.

7 · Verifying, and the one thing that lies

A wrong endpoint reads as success. The form posts to another origin, so nothing about the answer can be read back: a subscription, a 404, a typo'd username and the browser's own error page are the same event from this side. The frame loading is the whole receipt.

This is not a bug to fix — it is the price of having no server. It is also why the sheet says כמעט. בדקו את המייל. rather than claiming a subscription, and why double opt-in is doing real work: a reader whose sign-up never arrived finds out from the absence of the confirmation mail.

Two cases are knowable and are answered: a browser that reports itself offline is told before the form leaves, and a load that does not come within 8 seconds is a failure with the address kept.

The check, once, per environment

  1. Open an item page on a phone at the deployed URL, swipe to דעת הציבור, tap the pill.
  2. Enter a real address you can read. Send. You should see כמעט. בדקו את המייל.
  3. Open the provider's dashboard and confirm the subscriber is there. The screen is not evidence; the dashboard is.
  4. Confirm the double opt-in mail arrived, and that its from-address and subject are ones you are willing to have land in a stranger's inbox.
  5. If you set NEWSLETTER_PAGE_FIELD, check the subscriber's record carries the item URL with its #5.

8 · What the code does with them

filewhat it does
next.config.mjsReads the six plain names, refuses a non-https URL, and hands them out as NEXT_PUBLIC_*. One rule in one place, beside the environment and the pool.
lib/channels.tsThe app's view of them, and the only file that knows a mail list exists. NEWSLETTER_HIDDEN is parsed here into name/value pairs.
app/components/mobile/Updates.tsxThe sheet: lead, form, divider, rows, received state. Renders the hidden fields from configuration, and treats the frame's load as the receipt.
app/components/mobile/Opinion.tsxSlide 5's card, and the pill — drawn only when there is an endpoint.
app/components/mobile/Deck.tsxRenders the sheet beside the track, opens and closes it. Same gate.
tests/deck/updates.spec.tsTwelve tests. They know no host name: they answer everything that is not the site under test, and assert what the form carries rather than what the fields are called.
