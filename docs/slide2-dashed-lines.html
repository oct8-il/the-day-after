The dashed lines on slide 2

Three ways to author the same two lines. All three pass the coverage rule. They do not produce the same thing — and the one a writer would reach for first is the one that silently fails.

Every “parser returns” and “link preview” box below is real output from lib/annotation.ts, not an illustration.

The two lines, as the mock draws them

— אותה אזעקה נשמעה לרקטה ולחדירה, ולתושב לא הייתה דרך לדעת במה מדובר.עיתונות

— ההוראה הנדרשת בחדירה — לנעול, להחשיך, להסתתר — הפוכה מההוראה לרקטה.עיתונות

Note the second line. It carries three em-dashes: one that is meant to be a bullet, and two that are punctuation inside the sentence. Nothing distinguishes them.

Case B — the obvious way, and the trap

A markdown list, cite inside each item.silently renders as paragraphs

source

- [[אותה אזעקה נשמעה לרקטה ולחדירה]](t01-c05)
- [[ההוראה הנדרשת בחדירה — לנעול…]](t01-c06)

parser returns

pp

ul — the - never arrives.

why

The parser cuts the text into cite spans and the gaps between them, and only spans are drawn — “gaps carry no prose, so they are not here”. The - sits outside the [[…]], so it is a gap. It is dropped before the block parser ever sees it.

on the phone

אותה אזעקה נשמעה לרקטה ולחדירהעיתונות

ההוראה הנדרשת בחדירה — לנעול, להחשיך, להסתתר — הפוכהעיתונות

No bullet, no error, no warning.

This is the part worth writing down. Case B is what anyone writing markdown would type. It passes the validator, passes --strict, and quietly produces the wrong thing. The same trap applies to every annotated field — the stage overviews on slide 3 inherit it in Phase 5.

Case C — the marker inside the cite

The - moves inside the brackets.a real list

[[- ההוראה הנדרשת בחדירה — לנעול…]](t01-c06)

ulul

Real list blocks — but two lists of one item, one per span, not one list of two.

on the phone

  • אותה אזעקה נשמעה לרקטה ולחדירהעיתונות
  • ההוראה הנדרשת בחדירה — לנעול, להחשיך, להסתתר — הפוכהעיתונות

The marker is now a rendered bullet, in the accent, and it is not confusable with the punctuation inside the sentence.

what the link preview gets

אותה אזעקה נשמעה לרקטה ולחדירה ⏎ ההוראה הנדרשת בחדירה — לנעול, להחשיך, להסתתר — הפוכה

Clean — plainText strips list markers, so nothing stray reaches the OG description.

Cost: a screen reader announces “list, one item” twice.

So what it comes down to

Three true things: the design draws something that looks like a list; nothing in either pool is authored as one; and the annotation contract makes a real list awkward, because a list marker cannot live inside the thing a citation covers without being written inside the brackets.

What I'd do. Treat them as prose — case A, and change §5 to stop calling them “dashed lines”, which implies a list that does not exist. Then record case B in docs/annotations.html as a known trap, because it is silent and someone will hit it.

If you want them to be a real list — and the legibility argument for it is the second line, where one em-dash out of three is doing a different job — then it is case C plus a small change to Annotated to merge adjacent single-item lists. That is a renderer change, not a parser change, so it stays inside DIA-381's boundary. It is the better screen; it costs an authoring convention nobody would guess and one component change.
